GOOSE (Generic Object-Oriented Substation Event) is a publish/subscribe messaging protocol defined in IEC 61850-8-1 for real-time communication inside power substations. Unlike conventional network traffic, GOOSE frames are sent as multicast Ethernet packets — bypassing TCP/IP entirely — which enables event delivery in under 4 ms, satisfying the strict timing requirements of protection systems (class P2/P3 per IEC 61850-5).

Each RTU continuously publishes its binary state (heartbeat). When a fault is detected (overcurrent, short-circuit, …) the publisher immediately re-transmits the GOOSE PDU at an exponentially increasing rate, ensuring all subscribers open the correct circuit breakers within milliseconds — a scheme known as teleprotection (IEC 61850-90-1). The StNum counter increments on every state change; SqNum tracks retransmissions within the same event.

What happens when you press Trip RTU1:

  1. The dashboard sends POST /api/tpt/trip to the backend, which forwards it to the tpt-daemon running on RTU1 (192.168.30.7:8850).
  2. The daemon sets trip = True on the dataset and increments StNum — the IEC 61850 state-change counter. This single increment is the signal that tells every subscriber something has changed.
  3. RTU1 immediately fires a rapid-retransmit burst following the schedule mandated by the standard: T1 (2 ms) × 2 → T2 (10 ms) → T3 (100 ms) × 2, then falls back to the steady heartbeat at T0 = 1 s. Each retransmission increments SqNum while keeping StNum unchanged, so subscribers can distinguish retransmits from new events.
  4. The PDUs travel over the MPLS ACCESS layer (RTU1 → ACCESS1-1 → SR1-ACC1 → … → ACCESS1-3 → RTU2). RTU2's subscriber receives the burst, reads trip = True, logs the entry, and would assert its own relay output in a real substation.
  5. The panel updates within 1.5 s (next poll): RTU1's card turns red (TRIPPED), StNum is one higher than before, and the PDU log shows a burst of ⚡ TRIP rows with sequential SqNum values close together in time.
  6. If the MPLS path is broken while the trip is active, RTU2 stops receiving heartbeats; after 5 × T0 (5 s) the dashboard raises a COMM LOSS banner and the main-dashboard teleprotection state changes to open.

ⓘ Press Clear to de-assert the trip signal (another StNum increment, new retransmit burst, trip = False). Press Stop to halt both daemons; when RTU2 detects the heartbeat timeout it will raise COMM LOSS on its own.

IEC 60870-5-104 is the TCP/IP companion to IEC 60870-5-101, carrying SCADA supervisory data over routed IP networks (here: an MPLS L3VPN). Unlike IEC 61850 GOOSE — which uses multicast Ethernet for sub-4 ms protection — IEC 104 uses reliable TCP/2404 and targets monitoring workloads where latency is measured in seconds, not milliseconds.

The SCADA master (192.168.200.1/29) maintains a persistent TCP session to RTU1 (192.168.200.20/29) via the MPLS L3VPN: SCADA:eth1 → dc1 → SR1-ACC1 → ACCESS1-1 → RTU1:eth2 (primary), with automatic application-level failover to eth2 → dc2 if the primary link fails. Failover is driven by a TESTFR keepalive timeout (T3 = 20 s, T1 = 15 s); the service IP migrates between NICs via gratuitous ARP.

RTU1 publishes spontaneous M_ME_TF_1 (type 36) frames every second: a simulated 132 kV grid voltage at IOA 4001 with a CP56Time2a millisecond timestamp. The SCADA master acknowledges with S-frames every 8 I-frames (k = 8 window).
