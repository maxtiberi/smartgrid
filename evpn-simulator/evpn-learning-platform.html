Ethernet VPN (EVPN)
Piattaforma didattica basata su Nokia SR OS — RFC 7432 / RFC 8365
📡

Cos'è EVPN?

EVPN (Ethernet VPN) è una tecnologia di rete definita nell'RFC 7432 che utilizza MP-BGP come piano di controllo per veicolare informazioni di raggiungibilità MAC/IP tra i nodi di rete, eliminando il flooding tradizionale del Ethernet.

🔄

Perché EVPN?

Le soluzioni legacy (VPLS) apprendevano i MAC via data-plane flooding. EVPN porta il controllo nel piano BGP: apprendimento deterministico, ARP suppression, multi-homing attivo-attivo, mobilità VM, integrazione L2+L3.

🏗

Nokia SR OS

Nokia Service Router OS implementa EVPN su due piani dati: MPLS (per i service provider WAN) e VXLAN (per i data center). Questo corso usa VXLAN come underlay, tipico degli ambienti DC moderni.

Standard di riferimento
RFC 7432 — BGP MPLS-Based Ethernet VPN  ·  RFC 8365 — A Network Virtualization Overlay Solution Using EVPN  ·  RFC 9135 — Integrated Routing and Bridging in EVPN  ·  Nokia SROS Release 23.x
Vantaggi principali
✔ Apprendimento MAC via control-plane (niente flooding inutile)
✔ ARP/ND Suppression — riduzione del traffico BUM
✔ Multi-homing attivo-attivo (All-Active ESI)
✔ Mobilità host e VM tracking
✔ Integrazione L2 + L3 (IRB — Integrated Routing & Bridging)
✔ Scalabilità: milioni di MAC in tabelle BGP
Componenti fondamentali
► VTEP (VXLAN Tunnel EndPoint) — i nodi Leaf / PE
► VNI (VXLAN Network Identifier) — identifica il segmento L2
► EVI (EVPN Instance) — istanza EVPN per ogni servizio
► RD/RT — Route Distinguisher e Route Target BGP
► ESI (Ethernet Segment Identifier) — per il multi-homing
► RR (Route Reflector) — riflessione route BGP EVPN

Architettura EVPN
Piano di controllo BGP + Piano dati VXLAN
Piano di Controllo — MP-BGP EVPN

EVPN usa le MP-BGP NLRI (Network Layer Reachability Information) di tipo AFI=25 / SAFI=70 per distribuire informazioni di raggiungibilità. I Route Reflector (i nodi Spine) raccolgono e ridistribuiscono le route senza che i Leaf debbano avere sessioni iBGP full-mesh.
Tipi di Route EVPN (Route Types)

Ogni Route Type trasporta informazioni specifiche tramite BGP UPDATE.

Type 1 — Ethernet Auto-Discovery

RT-1 / EAD Route

Pubblicata per ogni Ethernet Segment (ESI). Usata per il Multi-Homing e per il fast-failover (aliasing/mass-withdraw).

Type 2 — MAC/IP Advertisement

RT-2 / MAC-IP Route

Trasporta indirizzo MAC e opzionalmente IP di un host. Sostituisce il flooding per l'apprendimento MAC. Abilita ARP Suppression.

Type 3 — Inclusive Multicast

RT-3 / IMET Route

Pubblicata da ogni VTEP al boot per annunciare la capacità di gestire traffico BUM (Broadcast/Unknown/Multicast) via Ingress Replication.

Type 5 — IP Prefix Route

RT-5 / IP Prefix

Distribuisce prefissi IP (L3) attraverso l'EVPN instance. Usata per l'integrazione L3 con i VRF (Integrated Routing & Bridging).

Piano Dati — VXLAN (RFC 7348)

Il traffico Ethernet originale del tenant viene incapsulato in UDP/IP con un header VXLAN che contiene il VNI (24 bit). Il trasporto avviene sull'underlay IP tra i VTEP (i nodi Leaf).

Flusso BUM (Broadcast/Unknown/Multicast)
In assenza di una voce MAC nel FDB, il primo frame verso un host sconosciuto viene replicato dal VTEP di ingresso verso tutti gli altri VTEP della stessa EVI (Ingress Replication). Dopo che la RT-2 è ricevuta tramite BGP, il traffico diventa unicast diretto tra i due VTEP.
ARP Suppression
Ogni VTEP mantiene una cache ARP locale alimentata dalle RT-2 ricevute via BGP. Quando un host fa un ARP request, il VTEP locale risponde direttamente senza inviare la richiesta sulla rete — eliminando il flooding ARP broadcast in tutta l'EVI.
